# Trump News — dossier de passage de relais

Document à fournir à Claude (nouveau compte, Projet Claude, ou Claude Code) pour reprendre le projet sans perte de contexte.

## 1. Le projet
Application desktop Windows qui, chaque jour : recherche les actualités sur Donald Trump, les recoupe, utilise un LLM local (**LM Studio**, API compatible OpenAI) pour analyser, génère un script, la voix, les visuels, monte une vidéo verticale 1080x1920 30 fps (TikTok / YouTube Shorts / Instagram Reels), génère titre/description/hashtags, publie via les API officielles et garde l'historique. Objectif final : démarrage du PC → `FULL AUTO` → minimum d'intervention humaine. Architecture 100 % modulaire (plugins) pour pouvoir plus tard traiter d'autres sujets.

Exigences de l'utilisateur : vrai code fonctionnel (pas de TODO), développement par phases, tests, SQLite, secrets hors Git, mode hors ligne autant que possible, aucun contournement des protections des plateformes, aucune fausse information, aucune manipulation d'audience.

## 2. Environnement de l'utilisateur
Windows 10/11 (invite de commandes), Python 3.12, `.venv` dans le dossier du projet (`run.bat` l'active), LM Studio avec modèles `qwen/qwen3-8b`, `qwen/qwen3-14b` (ne se charge pas : probablement VRAM), `qwen2.5-7b-instruct`, un modèle d'embedding ; FFmpeg installé via `winget install Gyan.FFmpeg` ; Edge TTS fonctionne (après `pip install -U edge-tts`). Dossier de travail : `C:\Users\<nom>\Downloads\trump-news-phase6\trump-news`. Fuseau : Europe/Paris. Langue de contenu : anglais par défaut (fr/es possibles).
Style de collaboration : l'utilisateur colle les sorties de terminal, attend des commandes complètes une par ligne, et dit « Continuer » pour passer à la suite.

## 3. Pipeline et décisions clés (ce qui existe, phases 1 à 7)
1. **Config/DB/LLM (P1)** : Pydantic + YAML + `.env`, SQLite/SQLAlchemy, `LMStudioProvider` (modèle `auto` = texte seulement, repli si un modèle ne charge pas, JSON strict avec réparation, retries/backoff, `<think>` retiré, embeddings).
2. **Actualités (P2)** : RSS, Google News RSS, GDELT ; normalisation ; dédoublonnage ; **regroupement en sujets** par mots + **embeddings** (seuil cosinus 0,8, repli lexical) ; un éditeur = une source (Reuters via Google News + Reuters RSS = 1) ; score configurable (importance, récence demi-vie 12 h, nombre de sources, pertinence, potentiel vidéo, pénalités doublons/incertitude/source faible).
3. **Fact-check (P3)** : une source par éditeur (texte complet > résumé > titre) → LLM extrait des affirmations avec **citation mot pour mot** par source → le code vérifie citation, existence de la source, chiffres, refuse les questions comme affirmations → **statuts par règles** (CONFIRMED ≥3 éditeurs fiables ; LIKELY ≥2 ; REPORTED 1 ; DISPUTED si contredit ; allégation/opinion plafonnées à REPORTED ; une même dépêche reprise compte 1) → verdict SAFE/CAUTION/BLOCKED (un sujet à une seule source en titre seul est BLOCKED).
4. **Script (P4)** : segments `hook→context→main→details→impact→conclusion`, chacun rattaché à des affirmations ; **validateur déterministe** (chiffres, attribution selon statut, DISPUTED présenté comme divergence, opinions encadrées, hook sans racolage, durée, doublons) + **passe de fidélité LLM** (détecte toute info ajoutée) ; boucle de correction avec retour d'erreurs ; segments fautifs supprimés ; durée **adaptée à la matière** (~30 mots/affirmation) ; styles (7), tons (4, opinion étiquetée, jamais de tiers inventé), durées (20-90 s), langues (en/fr/es).
5. **Voix (P5)** : `ITTSProvider` (Edge gratuit/en ligne avec timing des mots, Piper local, ElevenLabs payant) ; une voix par segment, pauses (0,4 s après le hook), concaténation WAV, normalisation -16 LUFS, chronologie stockée (table `narrations`), retries + repli automatique, cache, prosodie par style, prononciations.
6. **Visuels (P6)** : plan par segment calé sur la chronologie ; fournisseurs `user`, `wikimedia` (CC0/PD/CC BY, crédits auto), `pexels`, `ai` (Automatic1111, stylisé + bandeau IA indélébile), `cards` (cartes 1080x1920 avec étiquettes de statut traduites, carte des sources en conclusion, repli garanti) ; pas de répétition d'images (5 derniers plans) ; noms de médias jamais cherchés comme sujets de photo ; planche-contact.
7. **Montage (P7)** : `IVideoRenderer` (`FFmpegRenderer`) reçoit un `RenderJob` sans accès BDD ; passe 1 = un clip par prise (fond flouté 9:16 pour les photos non verticales, Ken Burns en 2x contre le tremblement de zoompan, cache 7 jours dans `data/videos/cache`) ; passe 2 = transitions xfade centrées sur les débuts de segment (durée vidéo = durée voix, calcul en images entières), sous-titres ASS mot par mot (texte du script aligné sur les mots Edge par difflib, sinon temps estimés), crédits photo et mention IA dans le même ASS, barre de progression, musique locale à licence déclarée avec ducking (`sidechaincompress`) + loudnorm, effet sonore optionnel ; 5 templates (`auto` selon le style) ; contrôle qualité déterministe (bloquants + score pondéré) → READY / NEEDS_REVIEW, rapport dans la nouvelle table `video_reports` + JSON ; refus explicite si pas de voix, pas de plan, plan calé sur une ancienne voix, image disparue ; aperçu 540x960 toujours NEEDS_REVIEW.

## 4. Historique des défauts trouvés par les tests réels (à ne pas réintroduire)
User-Agent HTTP avec accent → crash ; flux HTML accepté comme flux vide ; question de titre devenue « affirmation » ; sujet à une source/titre seul passé en CAUTION ; script qui brodait au-delà de l'affirmation (→ passe de fidélité) ; faux positifs de noms propres/chiffres en français ; loudnorm en 192 kHz ; `--force` qui ignorait le cache ; photos de « Reuters » cherchées comme sujet ; cartes redondantes consécutives ; config.yaml avec ancienne liste de flux qui masquait les nouveaux. Phase 7 : repli de modèle LM Studio bloqué quand `resolve_model()` avait déjà retenu un modèle trop gros ; carte des sources fusionnée (donc perdue) avec la carte précédente quand la conclusion n'avait pas de photo ; hook ouvrant sur une carte au lieu d'une photo. Machine sans fichier de pagination : un modèle 8b ne se charge plus dès que WSL/Docker tournent (« unable to allocate CUDA0 buffer »).
